## 8/28の測定結果

生データは同フォルダの `trial_log_20260828.csv`。

### トルク上限0.8のとき（15:08〜15:16、29回）

- 成功24回・失敗5回 → **成功率 82.8%**（95%信頼区間 65.5〜92.4%、Wilson）
- 振り上げ時間：中央値 1.6秒
- **失敗5件はすべてアーム角が±140°に到達したもの。** 振子角ガード到達・頭打ちは0件

### トルク上限1.5のとき（15:27〜15:37、通算28回）★この設定は使わない

- 最初の11回：失敗0
- **続く17回：4件失敗（すべて「アーム角±140°到達」＝上限0.8のときと同じ失敗の型）**
- 通算 24/28 = **成功率85.7%** … 上限0.8の82.8%とほぼ変わらない

**最初の11回連続成功は偶然の連続だった。** 11回では95%信頼区間の下限が74%しかなく、
この時点で「改善した」と判断したのは早計だった。
速くなった分アームの運動量も増えるため、引き戻す力を強めた効果と相殺されていたと考えられる。

**さらに実機で「速度が速くて怖い」という状態になった。**
数字の上での差はわずかなので、危険側に振れる設定を選ぶ理由がない。

### トルク上限1.0（最終・15:38に変更）

6回試行して5回成功・1回失敗（アーム角±140°到達）。**サンプルは少ない。**
**1.0でも「速度はかなり速い」（メンバーA）。** ただし実用上は問題ないと判断してこの値で確定した。
さらに下げたい場合は引数で 0.8 を渡せばコード変更なしで試せる。

#### ★長時間保持で分かったこと（15:43）

保持秒数を伸ばして試した2回で、**振り上げ後そのまま34.9秒・61.6秒と倒立を維持できた。**
61.6秒の回は最終的にアーム角±140°で停止しており、**倒立は保てているのに
アームだけがゆっくり流れ続けて可動範囲の端に達する**という形で終わっている。

これは下の「未解決の課題」にある**「保持中にアーム角が0°に戻らず居着く」問題と同じ現象**とみられる。
長時間のデモを行うなら、ここが実質的な制限時間になる。

#### なぜ速くなったのか

`uEnergy`（振り上げの押す力）は式で決まり最大0.81 N·mなので、
上限を1.5に上げても**振り上げの押す力自体は変わっていない**。
にもかかわらず速くなったのは、アームが遠くへ流れる前に引き戻せるようになり、
ポンピングの効率が上がったためと考えられる。
以前は引き戻し項が0.8で頭打ちになり、アームが流されっぱなしになっていた。

## この版で新しく入ったもの

1. **最小射影法によるキャッチ判定**（指導教員のご指摘）
   従来の「\|α\|<25° かつ \|α̇\|<3.0」という発見的な条件に代えて、
   W(x) = min( V(x), (E(x)−Er)² + c ) で切り替える。
   V(x)=xᵀPx はLQRのリヤプノフ関数で、P は `FurutaGains.RiccatiP`
   （リカッチ方程式の解。`design_and_simulate.py` が出力するようにした）。
   この振子ではエネルギー項が桁で無視できるほど小さいため、実質 V(x)≤c の判定になる。
   **c は必ず保証角度に直してから決めること**： \|α\| ≤ √(c · RiccatiPinvAlphaAlpha)

2. **試行の連続実行**
   1試行終わってもプログラムが終了せず、アームを初期位置へ戻して静止待ちに入り、
   次の試行を始める。安全確認は最初の1回だけ。Ctrl+Cで全体を終了。

3. **保持成功による自動終了**（既定5秒）

4. **trial_log.csv の列追加**：SwingGain・トルク上限・キャッチ角度・振子角ガード・c・キャッチ時V

5. **エンコーダ受信状態の表示**：CRCエラー数・欠落数・受信フレーム数

## 8/28に試して撤回したもの（再挑戦する場合の注意）

### 試行後の自動制動 → 削除

エネルギー整形則の目標エネルギーを E_top から E_bottom に差し替えて
振子を能動的に止める機能。**アームが暴走してマイコンに衝突させたため削除した。**

原因は、暴走を防いでいたアーム引き戻しバネ（閾値30°超・Kp=5.0）を
「制動トルクを潰している」と判断して弱めたこと。
このバネは8/26に判明していた暴走モード
（位置を戻す力が無いと sign(α̇cosα) が変わらない間ずっと同じ向きに押し続け、
0.4秒で±140°に達する）への保護そのものだった。

半自動（保持で自動終了 → アームを初期位置へ戻す → 静止待ち）でも
十分スムーズに回せるので、無理に自動化しなくてよい。

### アーム角ガードへの惰走予測 → 撤回

トルクを0にしてもアームは慣性で流れるので、その分 J_r·ω²/(2·τ_c) を
先取りして早めに止める、という案。**式が実態と合わず撤回した。**

実測アーム速度17.8 rad/s に対し式は惰走131°を予測するが、
それならアーム角81°から212°へ到達しているはずで、
8/28朝まで±140°のみで運用して衝突は一度も起きていない。
式が「クーロン摩擦だけで減速する自由なアーム」を仮定しており、
実際は振子との結合でエネルギーが移り、減速機の粘性摩擦もあるため大幅に過大予測していた。

検証せずに入れた結果、35回の測定で失敗8件が全てこのガードの誤停止
（それ以外の失敗はゼロ＝本来100%）になった。

**再度入れる場合は、まず実機で「トルクを切ってから何度流れるか」を
速度別に実測し、減速トルクを同定してからにすること。**
