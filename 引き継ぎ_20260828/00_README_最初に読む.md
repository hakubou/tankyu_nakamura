## この版の目玉：最小射影法によるキャッチ判定

指導教員のご指摘を受けて実装した。振り上げ制御からLQRへ切り替える条件を、
従来の経験則から**理論的な裏付けのあるもの**に置き換えている。

```
W(x) = min( V(x), (E(x) − Er)² + c )
```

- `V(x) = xᵀPx` … LQRのリヤプノフ関数。Pはリカッチ方程式の解
- `P` は `FurutaGains.RiccatiP` として `model/design_and_simulate.py` が出力する
- Vが小さい側（LQRが実際に立て直せる領域）でLQR、そうでなければエネルギー整形則

従来の「|α|<25° かつ |α̇|<3.0」は**振子の角度と角速度しか見ておらず、アーム側の状態を無視**していた。
V(x)ならθ・α・θ̇・α̇の4状態すべてがLQRの重みを通して評価される。

**★cの決め方（ここを間違えると危険）**

この振子ではエネルギー項が桁で無視できるほど小さく（真下でも7.3e-4 J²、対してVは真下で約480）、
実質 `V(x) ≤ c` の判定として働く。**cは必ず保証角度に換算してから決めること。**

```
V(x) ≤ c  ⟹  |α| ≤ √( c × RiccatiPinvAlphaAlpha )   [rad]
```

| c | 保証される\|α\| |
|---|---|
| 5 | 39.0° |
| **10（現在）** | **55.1°** |
| 20 | 78.0° |
| 100 | 174.4°（事実上無条件。**使ってはいけない**） |

Pの最小固有値が1.16e-3と極端に小さく、V(x)には「ほとんど増えない方向」がある。
そのため**Vが小さいことは角度が小さいことを意味しない**。
実際c=100にしたところ、真下付近（α=150°でもVは74まで下がる）で誤ってキャッチに切り替わった。

## ★手を出す前に読むこと（8/28に試して撤回した2件）

### 試行後の自動制動 → 削除した

エネルギー整形則の目標エネルギーをE_topからE_bottomに差し替えて振子を能動的に止める機能。
**アームが暴走してマイコンに衝突させたため機能ごと削除した。**

原因は、暴走を防いでいたアーム引き戻しバネ（閾値30°超・Kp=5.0）を
「制動トルクを潰している」と判断して弱めたこと。このバネは8/26に判明していた暴走モード
（位置を戻す力が無いと sign(α̇cosα) が変わらない間ずっと同じ向きに押し続け、0.4秒で±140°に達する）
への保護そのものだった。加えてゲインを300まで上げたため即飽和し、実質バンバン制御になっていた。

半自動（保持で自動終了 → アームを初期位置へ戻す → 静止待ち）で十分スムーズに回せる。
**無理に自動化しなくてよい。**

### アーム角ガードへの惰走予測 → 撤回した

トルクを0にしてもアームは慣性で流れるので、その分 `J_r·ω²/(2·τ_c)` を先取りして早めに止める案。
**式が実態と合わず撤回した。**

実測アーム速度17.8 rad/s に対し式は惰走131°を予測するが、それならアーム角81°から212°へ
到達しているはずで、実際には±140°のみの運用で衝突は起きていない。
式が「クーロン摩擦だけで減速する自由なアーム」を仮定しており、実際は振子との結合で
エネルギーが移り、減速機の粘性摩擦もあるため大幅に過大予測していた。

検証せずに入れた結果、35回の測定で失敗8件が全てこのガードの誤停止
（それ以外の失敗はゼロ＝本来100%）になり、測定時間を無駄にした。

**再度入れるなら、まず実機で「トルクを切ってから何度流れるか」を速度別に実測すること。**

### トルク上限の経緯

0.8 → 1.5 → 1.0 と動かした。**1.5は「速度が速くて怖い」状態になったので使わないこと。**
1.5で成功率が上がったように見えた（最初の11回が失敗ゼロ）が、
続く17回で4件失敗し通算85.7%と、0.8の82.8%とほぼ変わらなかった。
**11回程度のサンプルで判断してはいけない**（95%信頼区間の下限が74%しかない）。

現在は1.0。**引き戻し項は|θ|=39°の時点で既に上限に張り付く**ので、
バネ定数や閾値をいじっても効果はない。効くのは上限そのものを動かすこと。

## 未解決の課題

- **保持中にアーム角が0°へ戻らず27〜35°付近に留まる。**
  振子角αは±2〜4°で安定しているので倒立自体には影響しないが、
  **長時間の保持では最終的にアームが±140°に達して終わる**（61.6秒の回がこれ）。
  長時間デモを行うならここが実質的な制限時間になる。原因未調査。
- **制御周期の崩壊**：実行中に他のウィンドウをクリックすると、Windowsの電源スロットリングで
  制御周期が575Hz→130Hzに落ちる。原因は特定済みだがコード側の対策は未実装。
  **計測中は裏で何も動かさないこと。**
- **振り上げ時間が15〜28秒から1〜3秒に短縮した理由が未解明。** 8/28の14:13前後を境に変わった
- 外乱耐性の検証が途中。`BalanceControl` に `--log <path>` で時系列CSVを出す機能は追加済み
- ポスター用のグラフに使う時系列データはSwingUp側では未取得
- `dowel_angle=30` にするとSTL生成が落ちるバグ（当面 `999`＝ピン穴無効で運用）

## 安全上の注意

- **1回転はさせない**（配線が引っ掛かる）
- QUBEモジュールは借用品。分解しない・強い力をかけない
- **マイコンは配線の都合でアームの可動範囲の外へ動かせない。衝突のリスクが残っている**
- 実行前に、アームと振子の可動範囲に物・手・ケーブルが無いことを必ず確認する
- 電源スイッチにすぐ手が届く状態で実行する
